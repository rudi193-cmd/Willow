## The three themes

1. **Deliberate vendoring, no drift-guard.** Nearly every cross-repo clone
   carries a `"canonical lives at X, keep in sync"` docstring — intentional, not
   careless. But the sync is *manual*: no CI diffs the copies, so drift is the
   real threat, and it has *already happened* in the security primitives
   (HMAC encodings disagree, one friction detector is stale, one SOIL schema
   crashes the other, three ledgers hash different field-sets).
2. **Correct code, wrong perimeter.** The recurring hardening root cause: a real
   control guarding the wrong object — a session dict trusted by membership not
   content; `allow_db` with none of the protections `allow_net` has; CORS on an
   unauthenticated `0.0.0.0` bind; a gate the hosted apps read *around*; an
   attestation that checks string shape instead of truth.
3. **Unenforced controls — worse than prose.** Code that exists, looks
   authoritative, and never runs: a fully-built consent chain nothing calls;
   `consent.cloud_llm`/`lan` modeled and shown in the operator UI but never
   checked; a `verify()` with no production caller; a charter citing files that
   do not exist; hooks pointing at an absent machine path.

## A) DUPLICATION (ranked)

### A1 — `subject_consent` vendored in 3 repos, dead in one — HIGH
safe-app-store/libs/subject-consent (canonical) ↔ willow-mcp ↔ utety — ~430 near-identical lines ×3. In **utety it is dead-wired**: `permitted`/`grant`/`revoke` are imported only by tests; no production path calls them, so an operator's `revoke(...)` has **zero runtime effect**.
**Fix:** publish canonical as a package; willow-mcp + utety depend on it; wire it into utety's session path.

### A2 — utety carries two hash-chains and two consent models — HIGH
`core/store.py` (disclosure chain + flat `consent_status` column) vs `subject_consent/core.py` (a second, structurally different chain + 4 per-scope grants). Same learner, two "did anyone consent" representations, nothing keeps them in sync.
**Fix:** collapse to one chain and one consent representation.

### A3 — SOIL `records` schema drift crashes the "shared" store — HIGH
`willow-mcp/src/willow_mcp/db.py:76-87` defines `records(... deviation REAL, action TEXT ...)`; `jeles/corpus.py:38-45` defines the **same table** under the **same** `WILLOW_STORE_ROOT/<collection>/store.db` path with only `id,data,created_at,updated_at,deleted`. Both use `CREATE TABLE IF NOT EXISTS`, so whoever touches a collection **first wins**; if jeles wins, willow-mcp's `store_put` then fails `no such column: deviation`. jeles's docstring explicitly claims interop, so this is a live functional break, not theoretical.
**Fix:** one shared schema module; or jeles tolerates/creates the extra columns.

### A4 — `nest-seed` content pipeline, ~3,000 byte-identical lines — MED-HIGH
safe-app-store/apps/nest-seed/*.py ↔ willow-mcp/src/willow_mcp/nest/*.py, byte-identical, documented vendoring. radon confirms real complexity (`ingest.run` CC=43). **Fix:** extract as a package.

### A5 — safe-app-store per-app boilerplate explosion — MED
Same security-relevant utilities hand-rolled across ~10 apps instead of `libs/`: `safe_integration.py` "pigeon bus" ≈10 copies (nasa-archive's grew a `SAFESession` class the others lack); `*_paths.py` vault-resolver ≈10; `*_db.py` schema-guard ≥7 — **already drifted** (`re.fullmatch(r"[a-z_][a-z0-9_]*")` vs nasa-archive's `^[a-z_][a-z0-9_]{0,62}$`); `lattice_fallback.py` ×4 duplicating a model the-squirrel already **deleted as dead**.
**Fix:** promote to `libs/`: `willow-pigeon`, `vault-paths`, `pg-sqlite-shim`; delete lattice copies.

### A6 — three/four HMAC implementations that DISAGREE — MED (security)
Not just duplicated — **incompatible and unequally safe**:
- `nestor/signing.py:47` — `"\x1f".join((source_norm, target_text, verifier))`, naive delimiter join; fields can contain the delimiter (live forgery, **B4**). Opt-in, **fail-open** default.
- `willow-gate/__init__.py:169` and `willow-mcp/session_binder.py:104` — `json.dumps(..., separators=(",",":"))` **specifically** to prevent delimiter-shift collisions; signing **mandatory/fail-closed** once registered.
- the-squirrel `sap/core/gate.py:123` hand-rolls a 4th while already importing `willow_gate`.
An operator assuming one "signing guarantee" fleet-wide is wrong about Nestor.
**Fix:** one signing lib, canonical encoding, consistent fail-closed posture.

### A7 — three hash-chain ledgers with different coverage & verification — MED
- `willow-gate/custody.py` — full-event canonicalization + secret-redaction on append + Tier-4 GPG checkpoint; documents its Tier-1/Tier-4 boundary.
- `willow-mcp/governance_ledger.py:16-30` — hashes **only `event_type`+`content`**, excluding `project`/`id`/`created_at` from write *and* `verify()` → the FRANK `project` column can be altered without `frank_verify` detecting it.
- `nestor/ledger.py` — raw line bytes, no canonicalization, no redaction, and `verify()` has **no production caller** (**B7**).
**Fix:** converge on one chain design (canonicalize + redact + full-field hash + verify-on-boot).

### A8 — `friction_floor.py` vendored "byte-for-byte" but STALE — MED (live bug)
`willow-mcp/friction_floor.py` claims a diffable copy of willow-gate's, but is **missing the entire `stance_friction`/`_persona_polarity` fix** (willow-gate#9, 48.9%→84.2% accuracy). willow-mcp's `friction_scan` tool runs the **known-defective** detector. The textbook cost of manual vendoring without a CI diff.
**Fix:** re-sync + add a CI job that diffs vendored copies (minus header) and fails on drift.

### A9 — the trust model exists in 3 incompatible shapes — MED
willow-gate's 5-rung ladder (dataclass w/ `max_drift_ms`/`min_pass_count`/`allowed_tools`) vs willow-mcp `session_binder` `(name, read_only)` (drops every threshold) vs willow-mcp `gate.py` `PERMISSION_GROUPS` (orthogonal string ACL, no numeric rung). Nothing cross-checks a rung against a manifest group — an agent can be "Rookie" on the ladder and `full_access` in the manifest at once.
**Fix:** one identity→authority model; the others derive from it.

### A10 — doctrine duplication & drift — MED
Two live "Article XIV" files (`PROTECTED_AGENTS.md` + superseded `PROTECTED_PERSONS.md`); **"tier" means 3 things** (epistemic vs agent-trust vs manual example); `nest_rules.json` naming collision (unbuilt projection engine vs shipped file-classifier); sudo-invariant restated 5+ places; **"consent gate" is really 3 mechanisms** (`subject_consent`, legacy `consent.json`, egress `lease`); **"Independent Witness" overloaded** — flagged by *two* auditors: the charter (`CONSTITUTION.md:95`) requires demonstrated failure-mode divergence, but today's `jeles/reactions/conflict_scan.py` reuses the name for a ≥2-web-domain test satisfiable by one actor buying two domains.
**Fix:** one canonical home per concept + cross-links; rename the reaction's term and document its weaker bar.

### A11 — cleanup freebies — LOW
Dead `_archived/nestor/` copy in semantic-translator (**delete**) + a live copy that should `import nestor`; `_clean()` is a verbatim copy of the-squirrel's `sanitize()`; two disagreeing tokenizers (`jeles _tokens` token-set vs `nestor matcher` whole-string difflib) that can score the same phrase as match/no-match; `web_search.py` willow-mcp↔ask-jeles no provenance note; `jeles_persona.json` forked into utety-chat; `vault.py` Fernet store is a 3-generation copy-chain.

## B) HARDENING (ranked)

### B1 — willow-gate session dict is an unsigned mutable trust token — CRITICAL
`authorize_tool`/`check_out` (`__init__.py:281-359`) never re-fetch `self.sessions[nonce]`; they trust caller-passed `trust_level`/`granted_tools`/`tools_used`/`exports`. The only check is `nonce in self.sessions` (membership). **Attack:** hold the dict `check_in()` returns, set `trust_level=4, granted_tools={"admin"}`, call `authorize_tool(...)` → full admin, zero extra HMAC; the same forgery launders fabricated `tools_used`/`exports` past check-out reconciliation.
**Fix:** operate on `real = self.sessions[session["nonce"]]` only, ignoring caller bookkeeping — mirror `willow-mcp/session_binder.py`'s server-side + per-call-HMAC design. Effort **M**.

### B2 — willow-mcp `task_submit(allow_db=True)` = prod Postgres with no perimeter — HIGH
The net path requires `NET_PERMISSION` + `consent.internet_permitted()` + `lease.active()` + an operator-signed per-task envelope re-verified at shell launch. The db path (`server.py:1839`) requires **only** `gate.permitted(app_id, DB_PERMISSION)` — no lease, no consent, no envelope, no `ExecutorDbAuthorizer`. **Attack:** any app holding `task_db` runs `task_submit(task="psql ... -c 'DROP TABLE knowledge;'", allow_db=True)` — full DDL/DML on production Postgres, forever.
**Fix:** give `allow_db` the same three-key + signed-envelope + executor-recheck treatment as `allow_net`. Effort **M**.

### B3 — ≥8 hosted apps bypass the MCP gate, reading raw SOIL over the whole table — HIGH
`SELECT data FROM records WHERE deleted=0 AND data LIKE ?` over the **entire** table, no `WHERE collection=<own app_id>` (field-notes, nasa-archive, ask-jeles, law-gazelle, the-binder, utety-chat, private/public-ledger). Any untrusted app's `query("password")` returns other apps' lanes — the box's own MCP-first rule broken in code.
**Fix:** route through the gate-enforced tool, or a mandatory app-scoped filter. Touches the same copies as A5.

### B4 — delimiter-collision forgery in Nestor `signing.py:47` — HIGH (today's regression)
`"\x1f".join((source_norm, target_text, verifier))`: `source_norm` is normalized, `target_text`/`verifier` are not. A legit seal of `target_text="ok\x1fadmin", verifier="alice"` yields the **same HMAC** as forged `target_text="ok", verifier="admin\x1falice"` — forgeable without the key.
**Fix:** `json.dumps([...], separators=(",",":"))` or length-prefix (template: `session_binder.py:104-121`). Effort **S**.

### B5 — the Nestor seal check is bypassed one file over — HIGH (today's regression)
`best_sealed` calls `seal_is_valid`, but `reconcile.py:82` and `engine.py:27` filter on `status=="sealed"` **directly** — a forged sealed row is refused by `best_sealed` yet trusted as a reconciliation baseline *and* injected into the engine's system prompt (prompt-injection vector). Three internal copies of "what counts as sealed," two regressed.
**Fix:** a shared `memory._verified_sealed(matches)` all three call. Effort **S**.

### B6 — machine-corroborated nuggets masquerade as human-verified, and are forgeable — HIGH (today)
`jeles/corpus.py:180` hardcodes `"status":"verified"` for *any* non-empty `verified_by`; `to_search_hit:269` hardcodes `"confidence":"verified"`; `corpus_put` has **no ACL**. Any caller sets `verified_by="reviewed by security team"` (or the conflict-scan WITNESS tag) and it renders identically to a genuinely human-checked nugget. My `conflict_scan` stuffs machine provenance into the human-identity field.
**Fix:** a `verification_kind` (`human`|`machine`) field set by the **driver**, not caller-suppliable; `apply()` passes it; `to_search_hit`/`ask_corpus` surface `corroborated` vs `verified` distinctly. Effort **M**.

### B7 — utety consent gates nothing live; no age capture — HIGH
`loop.py`/`server.py` never check consent — an unconsented, un-age-verified child is fully tutored and persisted; the built consent chain (A1) is dead; no age surface exists, so the COPPA gate can never fire.
**Fix:** consent + age check at the top of the session path, fail-closed. Effort **M**.

### B8 — doctrine binding gaps — HIGH
`mem_ratify` (named Canon-promotion gate) **not built**; the live `knowledge_ingest` path has **no tier field, no quorum/witness** — any ACL-holder writes straight into shared-Postgres Canon. `CONSTITUTION.md:475` cites `core/n2n_packets.py` lines 69/111 as proof — **file does not exist**. Every `willow/.cursor/hooks.json` hook shells to `/home/sean-campbell/.../fylgja`, **absent**, while `CLAUDE.md:14` says "the gate outranks ORIENT."
**Fix:** build `mem_ratify`; correct/retire stale citations; delete or re-point dead hooks.

### B9 — `0.0.0.0` binds with CORS-only, no auth — HIGH
`public-ledger/main.py:247` and `vision-board/backend/main.py:195` bind `0.0.0.0`, CORS locked to localhost (a *browser* control), **no auth** — a direct `curl` from the segment gets the full API.
**Fix:** bind `127.0.0.1` or add authn. Effort **S**.

### B10 — Nestor `ledger.verify()` never called in production — HIGH
Tamper-evidence with no detection wired; the docstring says "run on read/boot," nothing does.
**Fix:** verify on process start, fail closed. Effort **S-M**.

### B11 — controls that look live but are no-ops — MED
- **willow-mcp `consent.cloud_llm` / `consent.lan`** — in `CONSENT_KEYS`, labeled in the operator panel ("Allow cloud AI access"), seeded to False, **never read** by any gated path (only `internet` is enforced). Toggling them protects nothing.
- **willow-mcp binding enforcement** (`WILLOW_MCP_ENFORCE_BINDING`) and **authority check** (`WILLOW_MCP_AUTHORITY_CHECK`) default **off** — exactly the "un-wired = loud ledger" case willow-gate warns about; and `AGENT_SERVICES.md` presents `authority_check` as live without disclosing the kill-switch.
**Fix:** wire the checks or remove the keys/claims so the surface stops implying protection.

### B12 — self-certified trust & non-tamper-evident audit — MED
- **willow-gate rungs are theater** — `pass_count`/`fail_count`/`drift` are agent-self-signed; `pass_count=999` on first check-in → Elder instantly. Source them from custody history.
- **willow-mcp `receipts.py`** (which H3 reconciliation reads) is a plain SQLite table, no hash-chain, in a repo that already has `governance_ledger`'s chain — a same-uid process edits it and `session_reconcile` reports `clean:true`. Hash-chain it.

### B13 — attestation & scan gaps in the promotion gate — MED (my `promote_check.py`)
`[A]` gates check **string shape not truth** (`author != verified_by` as strings; `promotion.json` **unsigned**; `repo_url` substring); `_toplevel_imports()` walks only `tree.body` (nested/`__import__`/relative imports hide egress); `semantic_seam` satisfied by an empty stub; no injection/secret lint wired though `tools/vault_leak_lint.py` exists.
**Fix:** sign+verify `promotion.json`; `ast.walk`; require a seam smoke-test; shell out to the lints. Effort **S**.

### B14 — Nestor signing/ledger residuals — MED/S
Signing silently no-ops with **no warning** if `NESTOR_SEAL_KEY` is unset (a deploy typo silently reopens B4 — add WARNING + `NESTOR_REQUIRE_SEAL_KEY=1`); the `/dev/null` fail-closed check is **symlink-bypassable** (`is_file()` follows links — use `realpath`+containment or `O_NOFOLLOW`).

### B15 — jeles hardening residuals (several on today's code) — MED/S
- **No collection-name validation** in `corpus.py:_conn()` → env-var path traversal (`JELES_CORPUS_COLLECTION=../../..`), while sibling `willow-mcp/db.py:_validate_collection` exists. Copy the regex. **S**.
- **conflict_scan sources include non-corroborating URLs** — all hits are attached, not just the corroborating domains, so a human can't tell which cleared the 2-domain bar. Filter to `domains`. **S**.
- **`_domain()` mishandles `co.uk`-style suffixes** → undercounts independent sources (fail-safe direction). Small public-suffix list. **S**.
- **`log_gap` uuid5 collision** when only ≤2-char tokens differ ("drug A" vs "drug B" collide, overwriting the earlier question). Hash the raw normalized string too. **S**.
- **`willow_mcp_client` forwards full `os.environ`** to the spawned willow-mcp subprocess — leaks `BRAVE_API_KEY`/`TAVILY_API_KEY` (from `search_adapter`) to a PATH-resolved binary. Pass a minimal env. **S**.
- **`search_adapter` has no response-size cap** before `resp.read()` — local-DoS surface for a fail-soft component. Bound the read. **S**.

### B16 — lower-severity, latent — LOW
SSRF: `source-trail/sources_db.py:328` `urlopen`s a stored URL with no allowlist while `willow-mcp/mai/parser.py:140` already has `_http_host_blocked` (dormant; wire before activating). utety egress = one unscoped env var flips internet for all learners + static unsigned bearer + `ConsentDenied` swallowed by bare `except`. SQL-injection-via-column-name latent in `semantic_translator/db.py:173` & `nasa-archive/pretraining.py:159` (safe today, allowlist columns). Placeholder `willow:willow` DB default left as a working runtime default in llmphysics + nasa-archive.
